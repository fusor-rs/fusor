These are complete source files. The component files define {{ state.example.get().tag() }}; the page files place that tag inside <App>, which starts the app. Four things connect HTML and Rust:

rust:component
Names the Rust struct. Its fields and methods are available as state.
{{ INTERPOLATION }}
Shows a Rust value as text or an attribute, and updates when the signals it reads change.
on:click · bind
Runs Rust when an event fires, or keeps an input and a signal in sync.
template!(…)
Connects the module to its HTML, so the compiler checks both together.

How it works

What you write, and what fusor does with it.

Markup in HTML files

Templates are .html files with the elements, classes, labels, and forms you would write anyway. Style them with CSS. Rust goes in double-brace bindings and attributes such as on:click.

HTML and Rust →

Logic in Rust modules

State is a Rust struct and behavior is its methods, with ordinary imports and types. The compiler checks every expression in your templates against that code.

Reusable components →

Fine-grained updates

Your Rust compiles to WebAssembly and runs in the browser. Each binding tracks the signals it reads. When a signal changes, the bindings that read it run again; the rest of the component does not re-render.

Signals and derived state →

Owned cleanup and async

Listeners, effects, and requests belong to the component that started them and stop when it is removed. <Async> can keep the previous view until related data is ready.
